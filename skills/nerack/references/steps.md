# Step semantics

- `validate` checks keys of any scope; request parameters (query, form, URL `:params`, top-level JSON body keys) are `input:name`. Success copies each value to its unprefixed name; failure writes `error:name` and raises `err_invalid` (400) after every item is checked. Files use `.types` (checked against the sniffed type) and `.max_bytes` instead of `.regex`. Checks beyond regex: a query, then `run()` calling `error_set()`.
- Uploads: each multipart file field is `input:<field>`, a one-row table `{name (untrusted), type (sniffed), size, data (blob)}`, in memory for the run only; over `env:max_upload_bytes` → `err_invalid`. Store with SQL (`{{#avatar}}insert ... values ({{name}}, {{type}}, {{data}}){{/avatar}}`), serve with `http_file_response()`. `public/` is never written at runtime.
- `sql_query` runs `<key>.sql` on any SQL engine (the database key decides it), or `<key>.<engine>.sql` when that variant exists for the database's engine (also for migrations and seeds; an override's plain file beats the module's variants). SQL assets are full Mustache, but every `{{x}}` (also `{{{x}}}`) is a bound parameter, never spliced; absent → NULL; a table binds as one list of its rows' first column (`id in ({{ids}})`; empty table → empty list). The result is always a table, even one row; omit `.context_key` when unused. `.error_on_empty` raises `err_not_found` (404) on zero rows. Each asset runs atomically and in isolation: a transaction is `begin; ... commit;` inside one asset, never across steps or items; a failure rolls it back. A multi-statement asset returns the last row-returning statement. Multi-row insert: `begin; {{#tags}}insert into tags (name) values ({{name}});{{/tags}} commit;`.
- Migrations and seeds run once each, in array order (tracked in `nerack_meta`); append new ones. Interpolating `.connection` (`file:{{user_id}}_notes.db?mode=rwc`) makes a database per tenant.
- `join` nests each parent record's matching children under a new field (default: the child table's key): `{todo:[{id}], comments:[{todo_id}]}` → `{todo:[{id, comments:[...]}]}`.
- `run` is short, non-blocking C on the request's own thread; `run_worker` runs on the thread pool for blocking or CPU-bound work, then resumes. `run_worker(.queue = "name")` runs calls on that queue one at a time, in order (per process), for a library that is not thread-safe.
- `nest` groups steps under one `.if_context_key`/`.unless_context_key`.
- `run_routine` runs a routine inline in the caller's context: it reads the caller's keys, and the keys it sets stay for the next steps. If it fails, its handlers run and the caller's run ends. `queue_task` queues a task, copying its `.accepts` keys from the caller, and continues.
- `http_fetch`: JSON responses parse into tables, text into strings. `.json` is a literal body whose values are JSON-escaped string contents (write `"{{title}}"` in quotes); `.json_table_key` serializes a context table; `.text` sends a context string. In `.url` and `http_redirect_external()`, values after `?` are percent-encoded and values before it are not, so keep request data out of the scheme, host, and path. `.json_record = true` sends a one-row `.json_table_key` table as an object (rules as `json`'s `.record`).
- `http_fetch` results: `http_code` is a table, one row per item (per row with `.map`), with field `http_code`. A 4xx/5xx raises `fetch_error` 1000 + status (`fetch_not_found` 1404, `fetch_not_authorized` 1401; unnamed ones by number), with the body still in `.context_key`; no response raises `fetch_timeout` 1601, `fetch_refused` 1602, `fetch_dns` 1603, `fetch_tls` 1604. A remote 404 never reaches an `http_not_found` handler. Handle them in `.errors`/`.repairs` like any code (`{fetch_not_authorized, {run(.call = refresh_token)}}`); unhandled, the client gets 500.
- `text`/`html`/`markdown`/`micron` render `<key>.txt`/`.html`/`.md`/`.mu` into `.context_key`, escaping `{{x}}` for the output (none in `text`). `context(key, tmpl)` renders a literal template like `format()`, checked at boot. `json` serializes a context table as an array of objects whatever its row count (one row: `[{...}]`); numbers and booleans from SQL columns or fetched JSON stay typed, everything else is a string. `.record = true`, for one-item endpoints, writes one row as an object `{...}`, no rows as `null`, several as the array.
- `http_response` sends a context value; `.status` defaults to `http_ok`, `.mime` to the resource's.
- `http_redirect` sends a 302 to a resource in its own module, `http_redirect_to` to another module's. `http_reroute`/`rns_reroute` run a resource of the same module in process: its `.all` and GET, keeping the whole context and the handled error's status. All fill the target's `:params` from context by key name.
- `http_headers`/`http_cookies` values interpolate; CR, LF, or NUL raises `err_internal`. Cookies are signed with `secret:cookie_secret`; tampered or unknown cookies are dropped, and valid ones come back as bare keys.
- `http_sse` writes to every client on `.channel`, or to the requester without one; consecutive calls build one record. A `.data` value with line breaks spans several `data:` lines.
- `datastar` patches the HTML in `.elements` into `.target` (id or selector; interpolates) for every client on `.channel`, or only the requester without one (validation errors), with `.mode` (default `outer_mode`; `remove_mode` needs no `.elements`). `.signals` names a one-row table merged into the client's signals; `.javascript` runs on the client.
- `.map = "table"` runs the step once per row, all rows concurrently, with the row's fields as bare `{{field}}`; a result key collects a table aligned to the input. `.map_context_key = "k"` also exposes the row as the one-row table `k` (for `.json_table_key`, `json()`).
- `.if_context_key = "k"` runs the step only when `k` is true, `.unless_context_key` only when false. False: missing, `nullptr`, `""`, `"0"`, `"false"`, a table with no rows. Template sections use the same rule, except opaque values are false there.
