# Events, routines, and tasks

- Events (`pubsub.h`) are durable. Names are global with one publisher each: `publish` declares the event and the keys it carries, `emit` fires it (only events the module publishes), and `subscribe` in any module names only the event. A subscriber sees the `.with` keys. Delivery is asynchronous, after the emitting run (never inside it), and at least once: a crash replays undelivered events, so subscribers should be idempotent.
- A routine is a named pipeline. `run_routine` runs it inline; `dispatch` (`task.h`) runs it as a durable task (resumed after a crash); `cron("name", "0 8 * * *")` dispatches it on a schedule (missed runs run once at boot; a run still going skips the next; instances sharing `task_db` on Postgres fire each run once). `.accepts` copies the caller's keys in, and the routine sees only those; `.gives` copies keys back to an inline caller (`run_routine`), ignored by `dispatch` and `cron`.
- A task checkpoints context after each step and resumes after a crash (on the next boot, or within about 30 s on another instance sharing `task_db`/`pubsub_db`, which also replays undelivered events) at the step that was running, which runs again: each step runs at least once, so make outside effects idempotent (an `Idempotency-Key` header with a stable id). Checkpoints keep strings, tables, and blobs; opaque values are dropped.
